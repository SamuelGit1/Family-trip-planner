# Family Trip Planner — Swipe, Match, Travel

**Date:** 2026-08-06
**Status:** Approved
**Build target:** 3 hours
**Tech stack:** Vanilla JS + CSS + HTML, GitHub Pages deploy

---

## 1. Overview

A mobile-first single-page web app that helps a family plan a 7-day trip by swiping through activities persona-by-persona (like Tinder for trip planning) and seeing where everyone's preferences overlap. The app supports **three modes** for sourcing activities:

| Mode | Activity Source | Destination |
|------|----------------|-------------|
| **Kaohsiung (Pre-loaded)** | 25 hand-curated activities + Taiwan gov API | Kaohsiung only |
| **AI (LLM)** | Claude API generates + Taiwan gov API | Kaohsiung (optimized for) |
| **Global (Web Search)** | Brave Search API → parsed into activity cards | **Any city in the world** |

All three modes feed into the same swipe → match board → itinerary pipeline.

**Family constraints:**
- Grandma (80s): cannot walk fast, needs frequent rest spots, max ~1 hour of walking
- Brother (5): short attention span, loves dinosaurs
- Mom (50s): loves beautiful views and shopping
- You (15): flexible, acts as tie-breaker

**Default location:** Kaohsiung, Taiwan (pre-loaded data). Global mode accepts any destination.

## 3. Screen Flow

### Screen 1: Setup

- **Mode selector:** 3 radio cards — "Kaohsiung (Pre-loaded)" | "AI Powered" | "Global Search"
- **Kaohsiung mode:** No additional inputs — uses pre-loaded activities + Taiwan gov API
- **AI mode:** Text input for Claude API key (stored in-memory only, never persisted). Activities generated by LLM + Taiwan gov API.
- **Global mode:** Text input for destination city/country ("Tokyo", "Paris", "Bangkok"). Optional: Brave Search API key input (free tier key). If no key provided, falls back to pre-loaded generic activities + user manually enters activities.
- Display 4 persona cards (Mom, Brother, Grandma, You) with their profiles — visible but not editable in v1
- "Start Swiping" button → triggers activity loading based on selected mode
- Data source indicator updates based on mode selection

### Screen 2: Swipe

- Card stack UI — one activity card at a time
- Each card shows: emoji, name, description, location, walking level, rest-spot indicator, cost, duration
- Swipe mechanics: drag left = pass, drag right = like; OR tap ❌ / ❤️ buttons
- Cards tilt and follow finger, fly off with spring animation on release
- **Persona switcher:** bottom tabs — Mom / Brother / Grandma / Me — glowing colored ring on active persona
- **Progress bar:** per persona — "Mom: 12/25 swiped"
- Each persona has an independent swipe queue
- "Done Swiping" button → proceeds to Match Board

### Screen 3: Match Board

- 4 persona rows with overlap strips between adjacent pairs
- Center section: "Everyone ❤️" — activities all 4 liked, with count badge
- Tap any overlap zone to expand and see activity list
- "Conflict zone": activities where preferences diverge (e.g., Mom likes, Grandma rejects)
- "Suggest compromise" button (AI mode: LLM suggests compromise activities; no-AI: tag engine finds nearby-tag matches)
- "Build Itinerary" button

### Screen 4: Itinerary Builder

- 7 day columns (Day 1 through Day 7)
- Drag activities from Match Board into day slots
- Each day shows:
  - **Grandma meter:** walking load — green (ok), yellow (warning), red (too much)
  - **Person coverage:** mini face icons showing who's happy that day
  - **Day total:** "3 activities, 5 hours, 🟢 grandma-friendly"
- "Family Happiness" gauge — aggregate across all 7 days
- Constraints enforced: if grandma walking load exceeds threshold, show warning

### Screen 5: Share

- Text summary of the 7-day itinerary
- Copy-to-clipboard button
- Optional: print-friendly view

## 4. Data Model

### Activity Object

```js
{
  id: "dream-mall",
  name: "Dream Mall",
  emoji: "🛍️",
  description: "Largest mall in Taiwan, rooftop amusement park with dinosaur exhibit",
  location: "Cianjhen District",
  walkingLevel: "low",        // "low" | "medium" | "high"
  restSpots: true,            // nearby seating/cafes available
  tags: ["shopping", "dinosaur", "indoor", "kid-friendly"],
  cost: "medium",             // "free" | "low" | "medium" | "high"
  duration: "half-day",       // "1h" | "2h" | "half-day" | "full-day"
  source: "preloaded"         // "preloaded" | "ai-generated" | "taiwan-api" | "web-search"
}
```

### Persona Profile

```js
{
  id: "grandma",
  name: "Grandma",
  emoji: "👵",
  color: "#FF8C00",          // orange
  tagWeights: {
    views: +2,
    restSpots: +999,         // effectively mandatory
    food: +1,
    cultural: +2,
    shopping: +1,
    nature: +1
  },
  constraints: {
    maxWalking: "low",       // rejects "medium" or "high"
    restRequired: true,      // auto-reject if restSpots is false
    maxDuration: "2h"        // auto-reject "half-day" or "full-day"
  }
}
```

## 5. Engine Logic

### Tag Matcher (No-AI Mode)

For each activity and each persona, compute a compatibility score:

```
score = sum(persona.tagWeights[tag] for each matching activity.tag)
      - penalty for constraint violations
```

- Constraint violation = instant reject (score = -Infinity)
- Grandma constraint: `walkingLevel !== "low"` OR `restSpots === false` → reject
- Brother constraint: `duration === "full-day"` → reject (short attention span)
- A swipe RIGHT = explicit like, stored regardless of score
- A swipe LEFT = explicit pass

### Overlap Detection

Pure set operations:
- `MomLikes ∩ BrotherLikes ∩ GrandmaLikes ∩ YouLikes` → "Everyone ❤️"
- `PersonA ∩ PersonB` → pairwise overlap strips
- Conflict detection: `PersonA.likes` where `PersonB.swipedLeft`

### Itinerary Scheduler

Greedy algorithm per day:
1. Prioritize "Everyone ❤️" activities first
2. Spread across 7 days evenly (no day overloaded)
3. Enforce grandma constraints per day: max 1 "medium" walking activity, total walking hours ≤ 2
4. Ensure brother gets at least one high-match activity per day
5. Flag days that violate constraints

### AI Mode

Three LLM calls (only when AI toggle is ON and API key provided):

1. **Activity generation** (optional, at setup):
   - Prompt: "Generate 20 activities in Kaohsiung suitable for a family with [persona descriptions]. Format as JSON with fields: name, description, location, walkingLevel, restSpots, tags, cost, duration."
   - Parsed into activity objects, merged with pre-loaded pool

2. **Re-rank on swipe completion**:
   - Prompt: "Here are activities each family member liked: [likes per persona]. Suggest 5 activities from the remaining pool that would satisfy everyone, and 3 compromise activities for conflicting preferences."

3. **Itinerary suggestion**:
   - Prompt: "Here are the family's matched activities with constraints. Build a 7-day itinerary respecting Grandma's walking limits. Format as JSON per day."

All calls go directly to the Anthropic API from the browser using the user's API key. The key is stored in a JavaScript variable (never in localStorage, never in the DOM).

### Kaohsiung Mode (Pre-loaded, Non-AI)

When Kaohsiung mode is selected without AI: all matching uses the tag engine, all itinerary building uses the greedy scheduler, and the activity pool comes from the 25 pre-loaded placeholders. The Taiwan government API is also called at setup to supplement with live event data (no auth needed). This is the zero-dependency path — no API keys required.

### Global Mode (Web Search)

When Global mode is selected, activities are fetched dynamically for any destination:

1. **User enters a destination** (e.g., "Tokyo", "Paris", "Bangkok") on the Setup screen
2. **Brave Search API** is called with 3 parallel queries:
   - `"best family-friendly activities in {destination}"`
   - `"things to do with young kids in {destination}"`
   - `"accessible attractions elderly friendly {destination}"`
3. **Results are parsed** into activity objects:
   - Each search result snippet is extracted
   - `searchFetcher.js` attempts to infer: name, description, location from the snippet text
   - Default values filled where inference fails: `walkingLevel: "medium"`, `restSpots: true`, `duration: "2h"`
   - Tags are auto-assigned based on keyword matching in the snippet (e.g., "museum" → `["cultural", "indoor"]`, "park" → `["nature", "kid-friendly"]`)
4. **Scored by tag engine** against each persona (same pipeline as other modes)
5. **Fed into the swipe deck** — user swipes and the rest is identical

**Brave Search API details:**
- Endpoint: `https://api.search.brave.com/res/v1/web/search`
- Auth: API key in `X-Subscription-Token` header
- Free tier: 2,000 queries/month (3 queries per destination = ~660 destinations/month)
- Rate limit: 1 query/second
- Returns: JSON with `web.results[]` — title, url, description (snippet)
- CORS: Supported (callable from browser)

**Fallback within Global mode:** If the Brave API key is missing or the quota is exhausted, Global mode falls back to prompting the user to manually type in 5-10 activities as free-text, which get parsed into cards. This ensures the mode is never fully broken.

**How searchFetcher.js works:**
```
fetchActivities(destination, braveApiKey)
  → Promise.all([query1, query2, query3])
  → deduplicate results by URL
  → parse each snippet into activity fields
  → auto-tag based on keyword matching
  → return Activity[]
```

## 6. UI/UX Details

### Card Swipe Animation
- Cards use CSS `transform: translate(x, y) rotate(deg)` on drag
- Release beyond threshold (40% of card width) → card flies off with `transition`
- Release below threshold → card springs back to center
- Swipe direction is stored: right = like, left = pass
- Next card fades in from below with slight scale-up

### Persona Switcher Tabs
- Horizontal row at bottom of swipe screen
- Active persona has a glowing colored ring + scale(1.1)
- Switching personas flips the card stack to that persona's remaining queue
- Each tab shows a mini progress bar

### Match Board Overlap Strips
- 4 horizontal bars (one per persona)
- Between each adjacent pair: a narrow strip showing overlap count
- Center "Everyone" badge: pulsing animation, large count number
- Tap any strip → expands to show activity list with emoji + name

### Itinerary Day Cards
- 7 columns on desktop, scrollable row on mobile
- Each day: header (Day 1, Day 2...), activity slots (drop targets), grandma meter
- Dragging an activity: card shrinks, follows cursor, drop zone highlights in persona color
- Invalid drop (grandma overload) → card snaps back, warning flash

### Responsive Design
- Mobile-first: single column, stacked layout
- Desktop: side-by-side day columns in itinerary view
- Swipe cards: always full-width, centered

## 7. Data Sources

### Source 1: Pre-loaded Activities (Kaohsiung Mode)
25 placeholder activities covering:
- Night markets (Liuhe, Ruifeng)
- Cultural sites (Lotus Pond, Fo Guang Shan)
- Shopping (Dream Mall, Shinkuchan)
- Nature (Cijin Island, Shoushan)
- Kid-friendly (dinosaur exhibits, parks)
- Grandma-friendly (indoor, seated, low-walking)

### Source 2: Taiwan Government Open Data API (Kaohsiung & AI Modes)
- Endpoint: `https://data.gov.tw/api/v2/rest/datastore`
- Dataset: Tourism events (ID #355)
- Filter: city=高雄市
- Called from browser via `fetch()`, no auth required
- Results merged into activity pool at setup time

### Source 3: AI-Generated (AI Mode Only)
- Claude API generates additional activities on-demand
- Merged with pre-loaded pool for swiping

### Source 4: Brave Search API (Global Mode)
- Endpoint: `https://api.search.brave.com/res/v1/web/search`
- Auth: `X-Subscription-Token` header (user-provided key)
- Free tier: 2,000 queries/month
- 3 parallel queries per destination → results parsed into activity cards
- Auto-tagging via keyword matching on snippet text
- Falls back to manual entry if API unavailable

### Source 5: Manual Entry (Universal Fallback)
- Simple text form: user pastes 5-10 activity names/descriptions
- Parsed into basic activity objects with default values
- Always available regardless of mode or API status

## 8. What's Out of Scope

- Real-time multi-device sync (Approach C — dropped for time)
- User accounts, login, database
- Backend server (no Express proxy needed since user provides own API key)
- Map integration (Google Maps/Leaflet) — nice-to-have but eats time
- Real booking or payments
- Weather integration
- Multi-language support
- Persistent sharing (URL shorteners, social media)
